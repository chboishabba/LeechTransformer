# Running the first genuine learned-MoE JQ1 experiment

## The missing corpus is recoverable from in-repo source owners

The earlier synthetic pipeline ran from random IDs because no local `.npy`
was present. That does NOT mean the source corpus is unrecoverable.

- The checked-in tokenizer `vocab/e8_morpheme_.model` is the original
  SentencePiece tokenizer, loaded by `tokenizer/tokenizer_utils.py`.
- `training/train.py` and `data_utils/streaming_dataset.py` use
  `HuggingFaceFW/fineweb-edu`: training skips the first 5000 streaming
  documents and validation takes those first 5000.
- Earlier `notebooks/lila_leechtransformer-new.py` samples
  `roneneldan/TinyStories` train; the actual TinyStories dataset has
  a disjoint validation split. TinyStories stories are generated by
  language models, but **these are real published training examples**,
  NOT randomly generated vocab IDs.
- The single available trained `data/best_model.pt` is DENSE, with no
  learned MoE histories. It must remain a frozen teacher and reference
  checkpoint. Sampling newly from the original corpus family does not
  reconstruct identical historic minibatches or prove which subset was
  used for that exact saved checkpoint.

`scripts/prepare_real_leech_tokens.py` streams each documented corpus
and produces disjoint, provenance-labelled `train_ids.npy` and
`heldout_ids.npy`. It checks tokenizer size against the checkpoint,
retains contiguous sequences with no padding or artificial tokens,
rejects duplicate documents across both sides, and stores SHA-256
source fingerprints, tokenizer hash, rows and split metadata.
TinyStories explicitly uses source train/validation; FineWeb-Edu uses
the original 5000-example reserved prefix. `local-text` mode requires
two genuinely separate text files. Dataset traffic/downloads are not
available from an isolated GitHub connector; run on your own workstation.

## One-command real corpus + two controlled geometric priors

Install `torch numpy datasets sentencepiece` in the same virtualenv as
your earlier 82-pass PR #4 checkout. Use your real checkpoint location
and *verified* configuration (the `/tmp/leech_dense_config.json`
already used by your successful local verifier is suitable if unchanged).

```bash
git fetch origin experiment/consumer-preserving-multiscale-codec-20261031
git switch experiment/consumer-preserving-multiscale-codec-20261031
python -m pip install -r requirements.txt

python -m unittest tests.test_prepare_real_leech_tokens -v

python -m scripts.run_real_moe_jq1_experiment \
  --checkpoint data/best_model.pt \
  --config /tmp/leech_dense_config.json \
  --source tinystories \
  --train-rows 1024 --heldout-rows 256 \
  --token-length 128 --epochs 3 --batch 2 \
  --experts 4 --top-k 2 --transition-rank 24 \
  --route-geometries c2_invariant punctured9_wave \
  --device cpu --layer 0 \
  --output-dir artifacts/real_moe_jq1
```

This foreground sequence:
1. streams real separate dataset splits using checked-in vocab;
2. freezes the exact dense teacher;
3. trains **all twelve** parity-MoE student layers twice using the same
   training tokens, seed, active-expert counts and learning schedule;
4. exports both candidate GPT models and measures held-out full-model
   next-token CE/logit drift against the dense teacher;
5. captures actual normalized hidden activations, history-before-step
   and selected expert IDs from each trained student;
6. benchmarks actual complete framed JQ1 raw/zlib/orbit against the
   geometric prior using both source-owned and peer-retained histories,
   with observed CPU encode/decode timing, request+return traffic, and
   1/10 Gbit/s ideal serialization + explicit 5 ms RTT assumptions.

Read `artifacts/real_moe_jq1/comparison.json`. Compare per-geometry
`heldout_quality` and `transport`. Both must matter: do NOT declare
a compressed but degraded student superior.

For the historical FineWeb-Edu pipeline use:
`--source fineweb-edu --fineweb-config default`.
`sample-10BT` is available as a smaller **new experimental** source,
not proof that the original trained checkpoint used that config.

For a smaller *real-data* integration run, choose
`--train-rows 64 --heldout-rows 32 --token-length 64 --epochs 1`;
label this real-text plumbing rather than a convergence or semantic
reasoning certificate.

## Important controls and remaining formal obligations

- The new parser/tests/one-shot orchestration are source-written on the
  branch; they have NOT yet been executed in your workstation.
  The prior user-confirmed **82 tests + 7 subtests** refer to commit
  `9dcaec6` and DO NOT certify this subsequent code.
- Keep train/validation disjoint, log source provenance and checkpoint
  SHA, and never replace missing training documents with random IDs.
- TinyStories is suitable for small-language-model transfer, **not** a
  paired semantic objection/argument benchmark. The Sophontic-like
  paired evaluation still needs its independently verified target labels.
- A trained student is genuinely learned if its student weights are
  updated on real text, but a useful model requires held-out CE, parity
  residuals, expert specialization, parameter/FLOP/latency comparisons,
  and broader multi-seed tasks. Historical expert states may be
  nontrivial without learning reusable orbits: measure that.
- All byte/hash exactness and source/receiver gating remain independent
  of future network authentication, true WAN measurements, and
  kernel-accepted Agda refinement of PyTorch.
- Original Leech-LILA and licensed code attribution remains to
  Anatolii Kornienko; DASHI finite Fourier/SSP15/369/dual and
  Sophontic donors retain their own primary mathematical roots.
